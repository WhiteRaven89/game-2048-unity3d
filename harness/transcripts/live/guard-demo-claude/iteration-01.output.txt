## Why the premise is stale

The bug the task describes is real, but it lives in the **legacy** code, not in Core. `Assets/Src/Managers/LevelManager.cs:696` `IsMoveLeft()` dereferences the right/up neighbours before bounds-testing them, and guards the wrong axis for each — so it throws exactly when the board fills.

`core/src/Game2048.Core/Rules.cs:IsGameOver` is the extraction that fixed it: every neighbour is bounds-checked *before* it is read (`c + 1 < board.Columns`, `r + 1 < board.Rows`). `git log` shows `Rules.cs` and `RulesGameOverTests.cs` both arrived in one commit — 15510bb, *"Extract a pure rules core from LevelManager, with the tests it never had."* The test was written against already-correct code and has never failed.

The old behaviour is deliberately pinned, not lost — `LegacyComparisonTests.cs:30` asserts `LegacyRules.IsMoveLeft` **still throws** on a full board, right beside a test asserting Core answers correctly. That's a characterization test of the original bug, and it passes too.

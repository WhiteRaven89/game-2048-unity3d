Done. `MaxTile` and `TilesMerged` are on `MoveResult`, both read-only.

**The change** — 55 added lines in one file, `core/src/Game2048.Core/MoveResult.cs`. Nothing else in the tree is touched.

**Why they're derived rather than stored.** Both values already exist in what `Move` computes, just not under a name:

- `TilesMerged` is `Merges.Count`. `Move` builds that list already.
- `MaxTile` is the largest cell of `Board`, the board `Move` just built.

I deliberately did *not* plumb either through the constructor. `Game.IsOver` in this codebase states the rule directly — "A cached flag is a second source of truth about the board, which is the mistake being corrected here; on a 4x4 grid the scan costs nothing worth having a bug for" — and `Board`'s own header is about two structures describing one fact being able to disagree. A stored `maxTile` on `MoveResult` would be exactly that second source, and its public constructor would let a caller pass one that contradicts the board. Deriving makes disagreement unrepresentable, and it leaves the constructor signature untouched, so the change is not API-breaking.

Two details a reviewer will stop on, both commented in place:
- `MaxTile` null-checks `Board` even though it's declared non-nullable — `default(MoveResult)` leaves it null, the same hole the existing `Merges` property already covers with `?? Array.Empty<Merge>()`.
- The name `TilesMerged` is ambiguous (pairs, or tiles consumed?). The task defines it as merge count, so `[2,2,2,2] → [4,4,0,0]` reports 2, not 4. The doc comment says so with that example, since the name alone doesn't.
